    40→## 1. Введение
    41→
    42→### 1.1. Цель
    43→
    44→Документ консолидирует все правила, инструменты и практики, необходимые для создания интерфейсов визуального уровня Dribbble: уровня Linear, Vercel, Raycast, Resend. Гайд объединяет фундаментальные принципы дизайна и полный технологический стек их реализации.
    45→
    46→### 1.2. Философия: правила важнее инструментов
    47→
    48→Крутой дизайн строится на правилах, а не на интуиции. Ни одна библиотека не спасёт интерфейс, в котором нарушена типографика, иерархия или сетка отступов. Поэтому порядок чтения строгий: сначала фундамент (раздел 2), потом слои и стек (разделы 3-13), и только затем полировка — эффекты, анимации, 3D.
    49→
    50→### 1.3. Как пользоваться гайдом
    51→
    52→- Проектируете новый продукт — читайте разделы по порядку.
    53→- Улучшаете существующий интерфейс — начните с приоритетов внедрения (раздел 18) и чек-листа (раздел 19).
    54→- Выбираете библиотеку — смотрите полную карту стека (приложение A) и раздел соответствующей категории.

    58→## 2. Фундамент дизайна: четыре кита
    59→
    60→### 2.1. Типографика — 80% дизайна
    61→
    62→Типографика влияет на восприятие интерфейса сильнее, чем любой другой фактор.
    63→
    64→**Обязательные правила:**
    65→
    66→- `line-height`: **1.5-1.7** для body-текста, **1.1-1.3** для крупных заголовков.
    67→- `letter-spacing`: слегка отрицательный (-0.01em ... -0.02em) для крупных заголовков, нейтральный для body.
    68→- Иерархия заголовков строится по шкале (см. раздел 5.3), а не "на глаз".
    69→- Максимальная длина строки body-текста: **65-75 символов**.
    70→
    71→**Шрифтовая система:**
    72→
    73→| Роль | Шрифт | Обоснование |
    74→|---|---|---|
    75→| Заголовки | **Geist** (Vercel) / **Satoshi** (Fontshare) / Cabinet Grotesk | Выразительные, геометричные; Inter "переиспользован до смерти" |
    76→| Body | **Inter** | Нейтральный, отлично читается |
    77→| Код | **JetBrains Mono** | Стандарт для моноширинного кода |
    78→
    79→Ключевой принцип: **замена заголовочного шрифта — минимальное изменение с максимальным эффектом**. Одно CSS-правило полностью меняет восприятие продукта.
    80→
    81→### 2.2. Пространство (Whitespace) и 8px-сетка
    82→
    83→- Все отступы и размеры кратны **8px** (допустим шаг 4px для мелких элементов).
    84→- Не лепите элементы друг к другу — воздух делает дизайн дорогим.
    85→- Если сомневаетесь — увеличивайте отступ, а не уменьшайте.
    86→
    87→Шкала отступов и утилиты Tailwind — в разделе 6.4.
    88→
    89→### 2.3. Цвет и контраст: правило 60-30-10
    90→
    91→- **60%** — основной цвет (фон, нейтральные поверхности).
    92→- **30%** — вторичный цвет (карточки, панели, приглушённые блоки).
    93→- **10%** — акцентный цвет (кнопки, ссылки, активные состояния).
    94→
    95→Всегда проверяйте контрастность текста: коэффициент не ниже **4.5:1** для основного текста и **3:1** для крупного (WCAG AA). Инструменты: Contrast Checker, встроенные аудиты браузеров.
    96→
    97→### 2.4. Визуальная иерархия: правило 3 секунд
    98→
    99→Пользователь за **3 секунды** должен понять:
   100→
   101→1. Куда смотреть (доминирующий элемент).
   102→2. Что читать (порядок чтения по убыванию веса).
   103→3. Куда нажать (одна главная цель на экран).
   104→
   105→### 2.5. Базовая литература
   106→
   107→**"Refactoring UI"** (Adam Wathan, Steve Schoger) — библия для разработчиков, которые хотят научиться дизайну. Все принципы из этого раздела раскрыты там с примерами.

   111→## 3. Архитектура визуальных слоёв
   112→
   113→Dribbble-уровень — это не одна библиотека, а **слои**. Каждый следующий слой усиливает предыдущий. Пропуск нижних слоёв делает верхние бессмысленными.
   114→
   115→| Слой | Состав | Вклад в результат |
   116→|---|---|---|
   117→| 1. База | shadcn/ui + Radix (или Untitled UI + React Aria), Tailwind CSS 4, Motion, Tremor | Около 40% визуального уровня |
   118→| 2. Анимированные компоненты | Magic UI: shimmer-border, animated beam, marquee, number ticker, dock, meteors, particles, border-beam | Переход с "хорошо" на "замечательно" |
   119→| 3. Типографика | Geist / Satoshi для заголовков, Inter для body, JetBrains Mono для кода | Выразительность, отстройка от шаблонных SaaS |
   120→| 4. Иконки | Phosphor Icons (duotone) как основной набор, Iconify как резерв | Глубина и премиальность |
   121→| 5. Текстуры и эффекты | Noise, glassmorphism, mesh-градиенты, grain, animated borders, spotlight, Lenis | "Тактильность" и кинематографичность |
   122→| 6. Иллюстрации и графика | Spline (3D hero), lottie-react (состояния), SVG-иллюстрации | "Тот самый" момент продукта |
   123→
   124→**Формула итогового рецепта:**
   125→
   126→```text
   127→Базовый стек (UI-кит + Tailwind 4 + Motion + Tremor)
   128→  + Magic UI          (анимированные компоненты)
   129→  + Phosphor Icons    (или Iconify)
   130→  + Geist / Satoshi   (заголовочный шрифт)
   131→  + Lenis             (smooth scroll)
   132→  + lottie-react      (анимации пустых состояний)
   133→  + SVG noise-текстура (CSS-фильтр, без зависимостей)
   134→  + Spline            (опционально, для hero)
   135→```

   139→## 4. Технологический стек: обзор и выбор UI-пути
   140→
   141→### 4.1. Фундамент
   142→
   143→| Технология | Роль |
   144→|---|---|
   145→| Next.js (App Router) | Фреймворк, маршрутизация, SSR/SSG, оптимизация |
   146→| React 19 | UI-рантайм |
   147→| TypeScript 5.9 | Строгая типизация |
   148→| Tailwind CSS 4 + @tailwindcss/postcss | Утилитарный CSS: системность отступов, цветов, радиусов |
   149→
   150→### 4.2. UI-слой: два равноценных пути
   151→
   152→**Путь A: shadcn/ui + Radix**
   153→
   154→| Библиотека | Роль |
   155→|---|---|
   156→| shadcn/ui | Компоненты через CLI (`npx shadcn add`), код принадлежит вам |
   157→| Radix UI | Headless-примитивы доступности под капотом shadcn |
   158→
   159→**Путь B: Untitled UI React + React Aria**
   160→
   161→| Библиотека | Версия | Роль |
   162→|---|---|---|
   163→| Untitled UI React | latest | Основа: кнопки, инпуты, карточки, таблицы, модалки, дропдауны, аватары, breadcrumbs |
   164→| React Aria | ^1.20 | Accessibility-примитивы (заменяет Radix) |
   165→
   166→**Критерии выбора:**
   167→
   168→| Критерий | shadcn/ui + Radix | Untitled UI + React Aria |
   169→|---|---|---|
   170→| Начальный вид | Требует настройки | Премиальный из коробки: скругления, тени, спейсинг настроены |
   171→| Контроль кода | Полный (компоненты в репозитории) | Ограничен API библиотеки |
   172→| Установка компонентов | CLI одной командой | Импорт из пакета |
   173→| Magic UI | Подключается через CLI | Ручная интеграция (перезапись примитивов) |
   174→| Кому подходит | Команды, которым нужен контроль | Быстрый запуск с "дизайнерским" видом |
   175→
   176→Оба пути строятся поверх Tailwind CSS 4 и совместимы со всем остальным стеком этого гайда.
   177→
   178→### 4.3. Утилиты слияния классов (нужны на обоих путях)
   179→
   180→| Библиотека | Версия | Роль |
   181→|---|---|---|
   182→| clsx | ^2.1 | Условное построение строк классов |
   183→| tailwind-merge | ^3.6 | Корректное слияние конфликтующих Tailwind-классов |
   184→| class-variance-authority (cva) | ^0.7 | Декларативные вариации компонентов |
   185→
   186→Утилита `cn()` — стандарт для всех компонентов проекта:
   187→
   188→```ts
   189→import { clsx, type ClassValue } from "clsx";
   190→import { twMerge } from "tailwind-merge";
   191→
   192→export function cn(...inputs: ClassValue[]) {
   193→  return twMerge(clsx(inputs));
   194→}
   195→```
   196→
   197→Вариации компонентов через cva:
   198→
   199→```tsx
   200→import { cva, type VariantProps } from "class-variance-authority";
   201→
   202→const buttonVariants = cva(
   203→  "inline-flex items-center justify-center rounded-lg font-medium transition-colors",
   204→  {
   205→    variants: {
   206→      variant: {
   207→        primary: "bg-primary text-primary-foreground hover:bg-primary/90",
   208→        outline: "border border-border bg-transparent hover:bg-muted",
   209→        ghost: "hover:bg-muted",
   210→      },
   211→      size: {
   212→        sm: "h-8 px-3 text-sm",
   213→        md: "h-10 px-4 text-sm",
   214→        lg: "h-12 px-6 text-base",
   215→      },
   216→    },
   217→    defaultVariants: { variant: "primary", size: "md" },
   218→  },
   219→);
   220→
   221→type ButtonProps = React.ButtonHTMLAttributes<HTMLButtonElement> &
   222→  VariantProps<typeof buttonVariants>;
   223→```

   227→## 5. Типографика и шрифты
   228→
   229→### 5.1. Шрифтовая система
   230→
   231→| Роль | Основной вариант | Альтернативы |
   232→|---|---|---|
   233→| Заголовки (display, h1-h3) | **Geist** | Satoshi, Cabinet Grotesk |
   234→| Body-текст | **Inter** | — |
   235→| Код, моноширинный | **JetBrains Mono** | — |
   236→
   237→Правило отстройки: Inter для заголовков "переиспользован до смерти" — каждый второй SaaS собран на нём. Выразительный гротеск для заголовков + нейтральный Inter для body — рабочая пара уровня Linear/Vercel.
   238→
   239→### 5.2. Подключение через next/font
   240→
   241→```tsx
   242→import { Geist, Inter, JetBrains_Mono } from "next/font/google";
   243→
   244→const geistSans = Geist({
   245→  variable: "--font-heading",
   246→  subsets: ["latin"],
   247→});
   248→
   249→const inter = Inter({
   250→  variable: "--font-body",
   251→  subsets: ["latin"],
   252→});
   253→
   254→const jetbrainsMono = JetBrains_Mono({
   255→  variable: "--font-mono",
   256→  subsets: ["latin"],
   257→});
   258→
   259→export default function RootLayout({
   260→  children,
   261→}: Readonly<{ children: React.ReactNode }>) {
   262→  return (
   263→    <html lang="ru">
   264→      <body
   265→        className={`${geistSans.variable} ${inter.variable} ${jetbrainsMono.variable} antialiased`}
   266→      >
   267→        {children}
   268→      </body>
   269→    </html>
   270→  );
   271→}
   272→```
   273→
   274→```css
   275→/* globals.css: назначение ролей */
   276→h1, h2, h3, h4 {
   277→  font-family: var(--font-heading), ui-sans-serif, system-ui, sans-serif;
   278→}
   279→
   280→body {
   281→  font-family: var(--font-body), ui-sans-serif, system-ui, sans-serif;
   282→}
   283→
   284→code, pre, kbd {
   285→  font-family: var(--font-mono), ui-monospace, monospace;
   286→}
   287→```

   289→### 5.3. Типографическая шкала
   290→
   291→| Уровень | Размер / line-height | letter-spacing | Tailwind |
   292→|---|---|---|---|
   293→| Display | 48-60px / 1.1 | -0.02em | `text-5xl md:text-6xl leading-[1.1] tracking-tight` |
   294→| H1 | 36-40px / 1.2 | -0.01em | `text-4xl leading-tight tracking-tight` |
   295→| H2 | 24-28px / 1.3 | -0.01em | `text-2xl md:text-3xl leading-snug tracking-tight` |
   296→| H3 | 20px / 1.4 | 0 | `text-xl leading-normal` |
   297→| Body | 16px / 1.6 | 0 | `text-base leading-relaxed` |
   298→| Small | 14px / 1.5 | 0 | `text-sm leading-normal` |
   299→| Caption | 12-13px / 1.5 | +0.01em | `text-xs text-muted-foreground` |
   300→
   301→### 5.4. Правила применения
   302→
   303→1. **Одно правило — один эффект:** замена заголовочного шрифта на Geist/Satoshi меняет восприятие продукта целиком.
   304→2. Заголовки не набираются Inter — только display-гротеск из системы.
   305→3. Не более двух семейств на странице + моноширинный для кода.
   306→4. Длина строки body — 65-75 символов (`max-w-prose` или `max-w-[65ch]`).

   310→## 6. Цвет, контраст и пространство
   311→
   312→### 6.1. Распределение 60-30-10 на практике
   313→
   314→| Доля | Роль | Пример в тёмной теме |
   315→|---|---|---|
   316→| 60% | Фон и базовые поверхности | background, зонах без содержимого |
   317→| 30% | Вторичные поверхности | карточки, панели, сайдбар, таблицы |
   318→| 10% | Акцент | primary-кнопки, ссылки, активные состояния, бейджи |
   319→
   320→Акцентный цвет не используется для декоративных элементов — только для действий и состояний.
   321→
   322→### 6.2. Контраст
   323→
   324→- Body-текст: **4.5:1** и выше (WCAG AA).
   325→- Крупный текст (18px+ / 14px bold+): **3:1** и выше.
   326→- Проверка: Contrast Checker, Lighthouse-аудит.
   327→- Приглушённый текст (`muted-foreground`) — тоже текст: проверяйте его контраст, а не только основной.
   328→
   329→### 6.3. Семантические токены через CSS-переменные
   330→
   331→Цвета применяются только через семантические токены, никогда — напрямую HEX-значениями в компонентах.
   332→
   333→```css
   334→:root {
   335→  --background: oklch(1 0 0);
   336→  --foreground: oklch(0.145 0 0);
   337→  --card: oklch(1 0 0);
   338→  --primary: oklch(0.205 0 0);
   339→  --primary-foreground: oklch(0.985 0 0);
   340→  --muted: oklch(0.97 0 0);
   341→  --muted-foreground: oklch(0.556 0 0);
   342→  --accent: oklch(0.97 0 0);
   343→  --border: oklch(0.922 0 0);
   344→  --ring: oklch(0.708 0 0);
   345→}
   346→
   347→.dark {
   348→  --background: oklch(0.145 0 0);
   349→  --foreground: oklch(0.985 0 0);
   350→  --card: oklch(0.205 0 0);
   351→  --primary: oklch(0.922 0 0);
   352→  --primary-foreground: oklch(0.205 0 0);
   353→  --muted: oklch(0.269 0 0);
   354→  --muted-foreground: oklch(0.708 0 0);
   355→  --accent: oklch(0.269 0 0);
   356→  --border: oklch(1 0 0 / 10%);
   357→  --ring: oklch(0.556 0 0);
   358→}
   359→```
   360→
   361→### 6.4. Шкала отступов (8px grid)
   362→
   363→| Токен | Значение | Tailwind | Применение |
   364→|---|---|---|---|
   365→| xs | 4px | `p-1 gap-1` | Плотные элементы: теги, иконки в кнопках |
   366→| sm | 8px | `p-2 gap-2` | Внутренние отступы мелких компонентов |
   367→| md | 12px | `p-3 gap-3` | Отступы внутри кнопок, инпутов |
   368→| lg | 16px | `p-4 gap-4` | Внутренние отступы карточек |
   369→| xl | 24px | `p-6 gap-6` | Отступы карточек, между блоками |
   370→| 2xl | 32px | `p-8 gap-8` | Между секциями внутри блока |
   371→| 3xl | 48px | `p-12 gap-12` | Между крупными секциями |
   372→| 4xl | 64px | `p-16 gap-16` | Секции лендинга |
   373→| 5xl | 96px | `p-24 gap-24` | Hero-блоки |
   374→
   375→### 6.5. Скругления и тени
   376→
   377→- Система радиусов: `--radius: 0.625rem` (10px); производные `sm/md/lg/xl` через `calc()`.
   378→- Тени — мягкие, многослойные, а не жёсткие чёрные: низкая непрозрачность + большой blur.
   379→- Единство важнее "красоты": один радиус для всех карточек, один для кнопок.

   463→### 7.6. Spotlight-hover
   464→
   465→Мягкое свечение следует за курсором на фоне карточки — как у Stripe и Linear.
   466→
   467→```tsx
   468→"use client";
   469→
   470→import { useState } from "react";
   471→import { cn } from "@/lib/utils";
   472→
   473→export function SpotlightCard({
   474→  children,
   475→  className,
   476→}: {
   477→  children: React.ReactNode;
   478→  className?: string;
   479→}) {
   480→  const [position, setPosition] = useState({ x: 0, y: 0 });
   481→
   482→  function handleMouseMove(event: React.MouseEvent<HTMLDivElement>) {
   483→    const rect = event.currentTarget.getBoundingClientRect();
   484→    setPosition({
   485→      x: event.clientX - rect.left,
   486→      y: event.clientY - rect.top,
   487→    });
   488→  }
   489→
   490→  return (
   491→    <div
   492→      onMouseMove={handleMouseMove}
   493→      className={cn("relative overflow-hidden rounded-xl", className)}
   494→    >
   495→      <div
   496→        className="pointer-events-none absolute -inset-px opacity-0 transition-opacity duration-300 group-hover:opacity-100"
   497→        style={{
   498→          background: `radial-gradient(240px circle at ${position.x}px ${position.y}px, rgba(255, 255, 255, 0.08), transparent 70%)`,
   499→        }}
   500→      />
   501→      {children}
   502→    </div>
   503→  );
   504→}
   505→```

   518→## 8. Анимации
   519→
   520→### 8.1. Принципы
   521→
   522→**Длительности:**
   523→
   524→| Тип | Длительность | Примеры |
   525→|---|---|---|
   526→| Микро-взаимодействия | 100-200ms | Hover кнопки, чекбокс |
   527→| Переходы состояний | 200-400ms | Появление дропдауна, смена таба |
   528→| Появление/исчезновение | 300-500ms | Модалки, страницы, тосты |
   529→| Декоративные фоны | 3-10s и бесконечно | Mesh, marquee, beam |
   530→
   531→**Жёсткие правила:**
   532→
   533→1. Анимируются только `transform` и `opacity` (compositor-friendly). `width`/`height`/`top`/`left` — запрещены.
   534→2. Easing: вход — `ease-out`, выход — `ease-in`, перемещение — `ease-in-out` или физика пружин.
   535→3. Обязательна поддержка `prefers-reduced-motion`: декоративные анимации отключаются.
   536→
   537→```css
   538→@media (prefers-reduced-motion: reduce) {
   539→  *,
   540→  *::before,
   541→  *::after {
   542→    animation-duration: 0.01ms !important;
   543→    transition-duration: 0.01ms !important;
   544→  }
   545→}
   546→```
   547→
   548→### 8.2. Motion / Framer Motion — база
   549→
   550→Версия: **^13** (пакет `motion` или `framer-motion`). Абсолютный маст-хэв для React.
   551→
   552→Освоение по порядку: `initial` / `animate` / `whileHover`, затем `AnimatePresence` (mount/unmount), затем `layout` (перестроения сеток) и `useInView` (reveal при скролле).
   553→
   554→Scroll-reveal секций:
   555→
   556→```tsx
   557→"use client";
   558→
   559→import { motion, useInView } from "framer-motion";
   560→import { useRef } from "react";
   561→
   562→export function Reveal({
   563→  children,
   564→  delay = 0,
   565→}: {
   566→  children: React.ReactNode;
   567→  delay?: number;
   568→}) {
   569→  const ref = useRef<HTMLDivElement>(null);
   570→  const inView = useInView(ref, { once: true, margin: "-80px" });
   571→
   572→  return (
   573→    <motion.div
   574→      ref={ref}
   575→      initial={{ opacity: 0, y: 24 }}
   576→      animate={inView ? { opacity: 1, y: 0 } : { opacity: 0, y: 24 }}
   577→      transition={{ duration: 0.5, delay, ease: [0.21, 0.47, 0.32, 0.98] }}
   578→    >
   579→      {children}
   580→    </motion.div>
   581→  );
   582→}
   583→```
   584→
   585→Staggered reveal карточек (каскад):
   586→
   587→```tsx
   588→const container = {
   589→  hidden: {},
   590→  show: { transition: { staggerChildren: 0.08 } },
   591→};
   592→
   593→const item = {
   594→  hidden: { opacity: 0, y: 20 },
   595→  show: { opacity: 1, y: 0, transition: { duration: 0.45 } },
   596→};
   597→
   598→export function CardGrid({ children }: { children: React.ReactNode }) {
   599→  return (
   600→    <motion.div
   601→      variants={container}
   602→      initial="hidden"
   603→      whileInView="show"
   604→      viewport={{ once: true }}
   605→      className="grid gap-4 sm:grid-cols-2 lg:grid-cols-3"
   606→    >
   607→      {children}
   608→    </motion.div>
   609→  );
   610→}
   611→```
   612→
   613→Смена шагов мастера (wizard) через `AnimatePresence`:
   614→
   615→```tsx
   616→"use client";
   617→
   618→import { AnimatePresence, motion } from "framer-motion";
   619→import { useState } from "react";
   620→
   621→const variants = {
   622→  enter: (direction: number) => ({ x: direction > 0 ? 320 : -320, opacity: 0 }),
   623→  center: { x: 0, opacity: 1 },
   624→  exit: (direction: number) => ({ x: direction > 0 ? -320 : 320, opacity: 0 }),
   625→};
   626→
   627→export function WizardSteps({ steps }: { steps: React.ReactNode[] }) {
   628→  const [[index, direction], setStep] = useState<[number, number]>([0, 0]);
   629→
   630→  function go(delta: number) {
   631→    setStep(([prev]) => [
   632→      Math.min(Math.max(prev + delta, 0), steps.length - 1),
   633→      delta,
   634→    ]);
   635→  }
   636→
   637→  return (
   638→    <div className="relative overflow-hidden">
   639→      <AnimatePresence mode="wait" custom={direction}>
   640→        <motion.div
   641→          key={index}
   642→          custom={direction}
   643→          variants={variants}
   644→          initial="enter"
   645→          animate="center"
   646→          exit="exit"
   647→          transition={{ duration: 0.3, ease: "easeInOut" }}
   648→        >
   649→          {steps[index]}
   650→        </motion.div>
   651→      </AnimatePresence>
   652→      <div className="mt-6 flex gap-2">
   653→        <button onClick={() => go(-1)}>Назад</button>
   654→        <button onClick={() => go(1)}>Далее</button>
   655→      </div>
   656→    </div>
   657→  );
   658→}
   659→```

   681→### 8.4. react-spring — физика
   682→
   683→Версия: **^9**. Физические пружины для drag-интеракций и elastic-эффектов: перетаскивание нод в графах, "резиновые" элементы, инерция. Используется точечно там, где линейные easing-кривые ощущаются "мёртвыми".
   684→
   685→### 8.5. auto-animate — списки
   686→
   687→Версия: **^0.8**. Одна обёртка — и DOM-перестройки списка (добавление, удаление, сортировка) анимируются автоматически, без ручных keyframe. Идеально для списков задач, таблиц, фильтров.
   688→
   689→```tsx
   690→import autoAnimate from "@formkit/auto-animate";
   691→import { useEffect, useRef } from "react";
   692→
   693→export function AnimatedList({ items }: { items: string[] }) {
   694→  const parent = useRef<HTMLUListElement>(null);
   695→
   696→  useEffect(() => {
   697→    if (parent.current) {
   698→      autoAnimate(parent.current);
   699→    }
   700→  }, [parent]);
   701→
   702→  return (
   703→    <ul ref={parent}>
   704→      {items.map((item) => (
   705→        <li key={item}>{item}</li>
   706→      ))}
   707→    </ul>
   708→  );
   709→}
   710→```

   712→### 8.6. Lenis — плавный скролл
   713→
   714→Версия: **^1**. Инерционный smooth scroll — базовый компонент "дорогого" ощущения всей страницы.
   715→
   716→```tsx
   717→"use client";
   718→
   719→import Lenis from "lenis";
   720→import { useEffect } from "react";
   721→
   722→export function SmoothScroll({ children }: { children: React.ReactNode }) {
   723→  useEffect(() => {
   724→    const lenis = new Lenis({
   725→      duration: 1.1,
   726→      easing: (t) => Math.min(1, 1.001 - Math.pow(2, -10 * t)),
   727→    });
   728→
   729→    function raf(time: number) {
   730→      lenis.raf(time);
   731→      requestAnimationFrame(raf);
   732→    }
   733→
   734→    const id = requestAnimationFrame(raf);
   735→    return () => {
   736→      cancelAnimationFrame(id);
   737→      lenis.destroy();
   738→    };
   739→  }, []);
   740→
   741→  return <>{children}</>;
   742→}
   743→```

   827→## 10. Node-based графы: React Flow
   828→
   829→### 10.1. Назначение
   830→
   831→| Библиотека | Версия | Роль |
   832→|---|---|---|
   833→| @xyflow/react | ^12.x | Node-based графы: многоэтапные процессы, пайплайны, схемы данных, mind maps |
   834→| @xyflow/react-controls | ^12.x | Мини-карта, зум, пан |
   835→| dagre | ^0.8 | Автоматическая раскладка нод (top-to-bottom / left-to-right) |
   836→
   837→React Flow превращает линейные индикаторы прогресса (степперы) в полноценный интерактивный граф: узлы — этапы процесса, рёбра — потоки данных между ними. Поддерживает drag & drop, кастомные ноды с превью, анимацию потока по рёбрам.
   838→
   839→### 10.2. Автолэйаут через dagre
   840→
   841→```ts
   842→import dagre from "@dagrejs/dagre";
   843→import type { Edge, Node } from "@xyflow/react";
   844→
   845→const NODE_WIDTH = 200;
   846→const NODE_HEIGHT = 80;
   847→
   848→export function applyAutoLayout(
   849→  nodes: Node[],
   850→  edges: Edge[],
   851→  direction: "TB" | "LR" = "LR",
   852→): Node[] {
   853→  const dagreGraph = new dagre.graphlib.Graph();
   854→  dagreGraph.setDefaultEdgeLabel(() => ({}));
   855→  dagreGraph.setGraph({ rankdir: direction, nodesep: 48, ranksep: 64 });
   856→
   857→  nodes.forEach((node) => {
   858→    dagreGraph.setNode(node.id, { width: NODE_WIDTH, height: NODE_HEIGHT });
   859→  });
   860→  edges.forEach((edge) => {
   861→    dagreGraph.setEdge(edge.source, edge.target);
   862→  });
   863→
   864→  dagre.layout(dagreGraph);
   865→
   866→  return nodes.map((node) => {
   867→    const position = dagreGraph.node(node.id);
   868→    return {
   869→      ...node,
   870→      position: {
   871→        x: position.x - NODE_WIDTH / 2,
   872→        y: position.y - NODE_HEIGHT / 2,
   873→      },
   874→    };
   875→  });
   876→}
   877→```

   880→

   882→"use client";

   982→## 13. Состояние, данные и формы
   983→
   984→### 13.1. Разделение ответственности
   985→
   986→| Библиотека | Версия | Зона ответственности |
   987→|---|---|---|
   988→| Zustand | ^5 | Клиентское состояние: UI-стор, настройки, локальный кэш |
   989→| TanStack React Query | ^5 | Серверное состояние: запросы, кэш, фоновые обновления, инвалидация |
   990→
   991→Правило: всё, что приходит с сервера, живёт в React Query. Всё, что порождается интерфейсом, — в Zustand. Дублирование запрещено.
   992→
   993→### 13.2. Формы: React Hook Form + Zod
   994→
   995→Версии: **react-hook-form ^7** + **zod ^4** (+ `@hookform/resolvers`). Совместимы и с shadcn/ui, и с Untitled UI.
   996→
   997→```tsx
   998→"use client";
   999→
  1000→import { zodResolver } from "@hookform/resolvers/zod";
  1001→import { useForm } from "react-hook-form";
  1002→import { z } from "zod";
  1003→
  1004→const schema = z.object({
  1005→  email: z.string().email("Введите корректный email"),
  1006→  password: z.string().min(8, "Минимум 8 символов"),
  1007→});
  1008→
  1009→type FormValues = z.infer<typeof schema>;
  1010→
  1011→export function LoginForm({ onSubmit }: { onSubmit: (values: FormValues) => Promise<void> }) {
  1012→  const {
  1013→    register,
  1014→    handleSubmit,
  1015→    formState: { errors, isSubmitting },
  1016→  } = useForm<FormValues>({
  1017→    resolver: zodResolver(schema),
  1018→  });
  1019→
  1020→  return (
  1021→    <form onSubmit={handleSubmit(onSubmit)} className="flex flex-col gap-4">
  1022→      <div className="flex flex-col gap-2">
  1023→        <label htmlFor="email">Email</label>
  1024→        <input id="email" type="email" {...register("email")} />
  1025→        {errors.email ? <span role="alert">{errors.email.message}</span> : null}
  1026→      </div>
  1027→      <div className="flex flex-col gap-2">
  1028→        <label htmlFor="password">Пароль</label>
  1029→        <input id="password" type="password" {...register("password")} />
  1030→        {errors.password ? (
  1031→          <span role="alert">{errors.password.message}</span>
  1032→        ) : null}
  1033→      </div>
  1034→      <button type="submit" disabled={isSubmitting}>
  1035→        {isSubmitting ? "Входим..." : "Войти"}
  1036→      </button>
  1037→    </form>
  1038→  );
  1039→}
  1040→```

  1044→## 14. Доступность (a11y)
  1045→
  1046→Доступность — признак профессионала и обязательное требование к качеству.
  1047→
  1048→- **Семантика:** `main`, `header`, `nav`, `section`, `article`; заголовки h1-h6 по иерархии без пропусков.
  1049→- **Клавиатура:** все интерактивные элементы доступны с клавиатуры; видимый `focus-visible` на каждом.
  1050→- **ARIA:** `aria-label` для иконочных кнопок, `aria-hidden` для декоративных иконок, `role="alert"` для ошибок.
  1051→- **Контраст:** раздел 6.2.
  1052→- **Reduced motion:** раздел 8.1.
  1053→- **Touch targets:** минимальная площадь касания 44x44px.
  1054→- **Экранные читалки:** `sr-only` классы для поясняющего текста.
  1055→- Оба UI-пути стека закрывают примитивы доступности: Radix (в shadcn) или React Aria (в Untitled UI).

  1060→

  1254→## Приложение B. Требования к Markdown-документации
  1255→
  1256→Все Markdown-документы проекта проходят ESLint-проверку. Правила автоматизированы и обязательны.
  1257→
  1258→### B.1. Запрещены эмодзи
  1259→
  1260→Правило: `unicode-policy/emoji-in-md` (error).
  1261→
  1262→- Эмодзи запрещены во всём документе, включая заголовки, таблицы и списки.
  1263→- Вместо эмодзи используйте текстовые теги: `[OK]`, `[FAIL]`, `[NEW]`, `[WARN]`.
  1264→
  1265→### B.2. Запрещены Unicode-символы графики
  1266→
  1267→Правило: `unicode-policy/unicode-graphics-in-md` (error).
  1268→
  1269→- Запрещены символы псевдографики: рамки, линии, блоки, геометрические фигуры, шрифты Брайля из диапазонов Unicode: Box Drawing (U+2500-U+257F), Block Elements (U+2580-U+259F), Geometric Shapes (U+25A0-U+25FF), Braille Patterns (U+2800-U+28FF).
  1270→- Для схем и карт используйте ASCII-графику, списки или таблицы Markdown.
  1271→
  1272→### B.3. Блоки кода обязаны иметь язык
  1273→
  1274→Правило: `code-block-language/require-language` (error).
  1275→
  1276→- Каждый fenced-блок ``` обязан указывать язык: `css`, `ts`, `tsx`, `json`, `bash`.
  1277→- Если язык неизвестен или это просто текст — указывайте `text`.
  1278→
  1279→### B.4. Прочее
  1280→
  1281→- Запрещены нерегулярные пробелы (неразрывные, zero-width) в коде и тексте.
  1282→- Для кода внутри документации действуют те же правила, что и для обычного кода: без эмодзи и псевдографики.
